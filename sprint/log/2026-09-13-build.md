## Built: Ask your summaries, not just your transcripts — [#13](https://github.com/Nirmaypanchal/rapport/pull/13)

The backlog item's evidence turned out to be easy to reproduce. On a scratch library with a real summary,
"What did we decide about pricing?" found **nothing at all** before this change: the transcript says "forty or fifty
euros a seat" and never the word "pricing", while the summary says "Pricing will be forty euros a seat". Only
`segments` were in the FTS index, so the one place the answer was already written was the one place Ask could not look.

- `summarize.split_summary()` cuts a summary into the blocks it is written in — a bullet with whatever is indented
  under it, or a paragraph — keeping the heading above each one. `**Decisions**`, which small models write instead of
  `## Decisions`, counts as a heading. A block over `MAX_BLOCK_CHARS` (1000) is cut on sentence ends, so an
  unstructured wall of text (an imported Granola note, say) cannot fill the prompt on its own.
- `db.index_summary()` puts those blocks in a new `summary_chunks` table with its own FTS5 index, and
  `insert_recording`/`update_recording` call it whenever the summary column changes. Both existing writers (the
  pipeline and the importer) already go through those two, so no writer has to remember, and the index cannot drift
  from the text. Regenerating a summary replaces what was indexed; clearing one clears it; deleting a recording
  cascades. Libraries written before today are backfilled the next time `Database()` opens them.
- `ask.retrieve()` is now where both Ask and the MCP `search` tool assemble excerpts.

**The decision the item left to Build — what a "moment" is for a summary — is that it is not one.** A summary has no
timestamp, so a summary excerpt carries `kind: "summary"`, no `segment_id`, no second to seek to, and its citation
opens that recording's Summary tab (`/?id=N&tab=summary`, a new query parameter the detail view honours) instead of
the audio. Pretending otherwise would have meant citing `00:00` for a sentence nobody said at `00:00`.

**The second decision: separate budgets, not one merged ranking.** bm25 over one-line turns and bm25 over summary
blocks are not the same scale, and comparing them would have been a guess dressed as a score. So up to three summary
blocks lead (at most one per recording, which spreads them over meetings) and moments fill the rest of the eight with
their own two-per-recording cap. The model is told which excerpts are summaries and asked to say "the summary says"
when only a summary supports a claim — a summary is already derived text, and quoting it as something a person said
is exactly the kind of small lie this feature must not tell.

MCP `search` returns both kinds, each shaped for what can be done with it: a `moment` keeps `at`/`start_sec`/`speaker`
for `get_transcript`, a `summary` carries its `heading` and points at `get_summary`. Still read-only, and
`test_no_tool_writes_to_the_library` still passes.
