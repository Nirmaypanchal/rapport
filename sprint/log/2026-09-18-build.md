## Built: Search finds summaries — [#27](https://github.com/Nirmaypanchal/rapport/pull/27)

`GET /api/search` answers `{moments, summaries}` instead of one list, with summaries capped at five. Two
arrays rather than one ranking, which the item asked for and which is also what `ask.retrieve` already does:
the two bm25 scores come from different FTS tables, one over one-line turns and one over paragraphs, so
ordering them against each other would be a number that means nothing.

Three things needed deciding rather than guessing:

1. **A failure in either half is still one 400.** Both halves are computed in one expression inside the
   route's existing `try`, so a raising `search_summaries` cannot come back as `{"moments": […]}` with the
   other key missing — which the UI would have rendered as "nothing in your summaries matched". The test for
   it monkeypatches the raise, because nothing a user can type reaches that branch any more: every term is
   quoted before it gets to `MATCH`, and I checked in a scratch SQLite that `""""`, `"*"`, `"?"` and
   `"NEAR"` all come back empty rather than erroring. Asserting a 400 on a typed query would have been a
   test of something that cannot happen.
2. **`scripts/e2e.py` is a caller of this route, and nothing typechecks it.** It read the response as a
   list; it now reads `["moments"]`. `tsc` could never have caught that, and the nightly is the only thing
   that runs it — so grepping for the route *string* rather than the TypeScript type is what found it. The
   MCP `search` tool is untouched: it opens SQLite directly, not HTTP.
3. **The summary card is one component now, not a copy.** `ask-panel.tsx`'s `Source` rendered the summary
   case inline with three ternaries; that case moved to `frontend/src/components/summary-hit.tsx`, which
   takes the citation number as a `badge` prop and a `dim` flag. Ask passes both, Search passes neither, and
   the shared card has no idea which page found it — which is the only way the two lists stay the same
   thing. A titleless recording now shows date and time in a summary card exactly as it already does in the
   moment cards beside it.

In the results list summaries lead and moments follow: one continuous list, no divider, no second tab, told
apart by the badge on the card, per the 2026-09-14 decision.

One tidy-up beside the work: `api.ts` carried two stacked docstrings above `AskSource`, a leftover from
[#13](https://github.com/Nirmaypanchal/rapport/pull/13). Inserting `SummaryHit` above them made the first
one look like it documented the wrong type, so it is gone.
