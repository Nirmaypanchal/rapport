## Built: Zoom, Google Meet and OneDrive — [#29](https://github.com/Nirmaypanchal/rapport/pull/29)

Three tiles' worth of detection, no new mechanism: Zoom writes local recordings to `~/Documents/Zoom`,
Meet writes into `Meet Recordings` inside Google Drive, and watched folders have existed since the first
week. What was missing was the one click that says "that folder, yes". Every acceptance criterion met,
with one substitution and one decision the criteria left implicit:

1. **The spec named a file that had moved, and the move changed the question.** It asked for the candidate
   in `server.py`'s `fs_roots`; [#28](https://github.com/Nirmaypanchal/rapport/pull/28) moved that list into
   `rapport/sources.py` the day before. That is trivia on its own — but there are now *two* lists there, and
   the spec does not say which. `fs_roots` is browse shortcuts (Downloads, Desktop); `cloud_roots` is the
   places a watched folder is *filed* under. Put Zoom in the first and its tile counts nothing, its
   recordings read "watched folder", and no Zoom template is expressible — which is precisely the
   zero-count bug #28 was about. So Zoom went in the place list, and the list is no longer only cloud
   services: **`cloud_roots()` is now `place_roots()`**, and the difference between the two lists is exactly
   "does it have a tile, and could you set a template for it". A Zoom meeting is filed under `zoom`.
2. **One watch covers every meeting**, because `dji.audio_files` uses `rglob` and Zoom writes one folder per
   meeting. Checked rather than assumed; it is what makes the tile worth having instead of a folder picker.
3. **Google Meet stayed inside the Google Drive tile**, as the item asked. The criteria said "one sentence in
   that tile's blurb", but the blurb is also the dialog's description and is `line-clamp-2` on the tile, so
   the tile keeps a short line ("Watch a synced folder, Google Meet's included") and `FolderPanel` gained an
   optional `hint` — a dashed-border note in the existing explanatory-state style — for the `Meet Recordings`
   detail. Zoom uses the same hint for Zoom's own wording (Record → **Record on this Computer**) and for the
   fact that a *cloud* recording leaves nothing on the Mac.
4. **Three places named the tiles, and one of them was already wrong.** The panel dispatch, `state()`, and
   the "Any folder" tile's filter each listed `icloud`/`dropbox`/`googledrive` by hand — so a OneDrive folder
   would have counted under its own tile *and* under "Any folder". They read one `FOLDER_PLACES` list now,
   and `FolderPanel` takes the tile's name rather than a three-way conditional that would have told a Mac
   without Zoom that "Google Drive is not set up".
5. **The page and the backend disagreed about what is inside a folder.** `sources-view.tsx` used
   `startsWith`, which the backend deliberately does not (`~/Dropbox Archive` is not inside `~/Dropbox`).
   Both match at a separator now. Nobody has hit it; a tile and the recording it filed would have disagreed.

Beside it: the USB tile and the README said "Zoom" for the H-series recorders, which is a different Zoom —
both now say "Zoom H-series". `BRAND_APPS` gained `zoom.us.app` so the tile shows the real app icon, falling
back to the simple-icons mark; OneDrive has no simple-icons mark any more, so it uses the Lucide `Cloud` in
the same `{ kind: "icon" }` shape as `usb`, `folder` and `files`.
