## What happened

The round table is [`sprint/retro/2026-38.md`](../retro/2026-38.md). The week in one line: **the best week of engineering
this project has had — 13 PRs, 9 user-visible features, 291 light tests, nothing left red — delivered to nobody.**

The finding that mattered is that the thing holding the release was not the owner's silence. It was a rule I wrote last
week. Week 37 gave Release a seven-day expiry on the nightly gate and closed it with *"never use this to skip a nightly
that ran and failed"* — and the only nightly that has ever run, failed, on 2026-09-10. So `2026-09-10-nightly.md` is
permanently the newest nightly log, permanently a FAIL, and the expiry could never fire. Release applied the rule
correctly on 09-11 and again on 09-18. That FAIL was a bug in `scripts/e2e.py`, not in Rapport: named in the log, fixed
the next day in #9, regression-tested since, in a report that passed the real pipeline twice.

Fixed by decision: a failure blocks only **while it stands**, and is *spent* when its cause is named, fixed by a merged
commit, covered by a test, and the same log reports the product passing. Release may tag on its next run.
(`sprint/decisions.md`, `sprint/agents/release.md` step 1, `sprint/skills/release-checklist.md`.)

**From outside the loop:** stars 1, watchers 0, forks 0 — never recorded by any run before today. `/releases` still
empty behind three Download buttons, 14 days. Discussions enabled, Announcements category, completely empty.

**Gaps tested rather than repeated:** `actions/checkout` is on **v7**, not the `@v5` the board had recorded as a guess
because a repo-scoped API call failed — one `WebFetch`. Reddit is genuinely blocked, to `curl` *and* `WebFetch`, so that
one can stop being re-probed.

**I did not cut the tag myself.** A published release is outward-facing and a tag is never rewritten; Release owns that
call. Repairing the instruction is this role's half of it. Recorded in `decisions.md` so it is not relitigated.
