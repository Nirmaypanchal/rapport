## Built: one vocabulary for sources — [#28](https://github.com/Nirmaypanchal/rapport/pull/28)

`rapport/sources.py` is the one translation between the two words for "source": the `recordings.source`
column keeps naming the *mechanism* (`folder`, `microphone`, `file`) because dedup and the connectors read
it, and `source_key(source, source_volume, roots)` answers the *place* the Sources page names (`icloud`,
`mic`, `files`). A watched folder resolves by matching its stored watched path against the cloud roots —
the same list `/api/fs/roots` answers, which moved into the module so the page and the filing cannot
disagree about one folder. Every acceptance criterion as written; four things needed deciding rather than
guessing:

1. **Renaming what a function returns renames it for readers the item never mentioned.** The acceptance
   named `db.source_counts()`, the templates route and `template_for`. But `source_counts()` also feeds
   `/api/sources`, and `sources-view.tsx` was *already* reading it by tile id — `src.counts.microphone`
   in the mic panel, against counts keyed `microphone`… which happened to match, and `counts.mic` would
   not have. Reading the consumers rather than the callers is what caught it; the mic panel's "N recorded
   here so far" is now keyed `mic` and the tile counts mean something for the first time. Filed as the
   lesson in `sprint/skills/build-codebase-patterns.md`: grep for the *values* a function returns.
2. **The UI needs the resolved key, and cannot compute it.** `defaultTemplateFor(r.source, tpl)` would
   have silently stopped matching for every microphone, file and folder recording once the map was keyed
   by place — and only the Mac knows where its iCloud Drive is, so the frontend cannot resolve a folder
   itself. So `source_place` rides on every recording payload (`/api/recordings`, one recording, and the
   PATCH response), resolved once per list rather than per row, and the UI stays a lookup.
3. **A settings file written in the old words keeps working.** `summary_template_by_source` is read
   through `resolve_by_source`, which reads each key as a place — a place resolves to itself, so it costs
   one dict comprehension and a `{"microphone": "journal"}` map written by an older build still applies
   instead of quietly doing nothing. Nothing has ever been released, so this protects the owner's own
   dev library rather than users, but the rule in this codebase is that `settings.json` is a file a user
   can edit and validation on write is never the only defence.
4. **OneDrive resolves as a place although it has no tile.** It has been in `/api/fs/roots` since the page
   was built and no tile ever used it. Filing its recordings under `onedrive` is more accurate than
   "watched folder", and its folders stay manageable under the generic tile — so both halves are right and
   the gap is the missing tile, now on the board under Next beside the Zoom item it resembles.

Beside the work: the badge in the recordings list moved to `sourceTag()` in `format.ts` and shows the place,
so a watched Dropbox recording says `dropbox` rather than `folder`. The MCP tools' `source` field is
deliberately unchanged — that is a data API over the column, not a picker.
