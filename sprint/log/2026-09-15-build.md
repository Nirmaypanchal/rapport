## Built 1: the subreddit check that refused r/rapport itself — [#17](https://github.com/Nirmaypanchal/rapport/pull/17)

Community found this live on 09-14 ([#16](https://github.com/Nirmaypanchal/rapport/issues/16)): the first weekly
update failed with `subreddit 'apport' is not allowed`. `.lstrip("r/")` strips leading `r` and `/` *characters*, not
the prefix, so the literal word `rapport` — the only value any real outbox file carries — became `apport` and failed
the script's own allow-list, before a token was ever requested and regardless of the missing credentials (#3).

- `subreddit()` removes an `r/` or `/r/` prefix and nothing else.
- **The adjacent bug needed a rule, not a patch.** `parse()` cut a value at the first `#` *unless* it started with
  the letter `t` — a guard for `parent: t1_…` fullnames that truncated any value beginning with a lowercase `t`
  word ("the week in Rapport" → "the"). A frontmatter comment is now a `#` standing alone with whitespace on both
  sides, which covers the documented `kind: comment  # post | comment` style, keeps a hash inside the text
  (`Rapport #1`), and makes the `t` case unnecessary. The cost is named in the docstring: a title that really wants
  a space-then-hash cannot have one. That trade felt right for a file format whose only free-text field is a title.
- The decision about a file — post it, refuse it — moved into `prepare()`, one step short of the network, and
  `main()` grew `--outbox` and `--dry-run`. That is what made the whole path testable without credentials and
  without posting anything, which is the reason this bug lived until a real post hit it.
- Closed #16 with what changed. `sprint/reddit/failed/2026-09-14-weekly-update.md` now passes the check that
  refused it and is ready to resend whenever Community wants it.

## Built 2: notice when the nightly goes quiet — [#18](https://github.com/Nirmaypanchal/rapport/pull/18)

A daily workflow opens one issue when the newest `sprint/log/*-nightly.md` is more than 48 hours old, and closes it
again when a log lands. `scripts/nightly_watchdog.py` holds the decision; the YAML is checkout plus one `run:` line.

- **The date in the file name is the age, not the mtime.** A fresh clone stamps every file with the checkout time,
  so mtime reports a week-old log as seconds old. That date counts as 00:00 UTC, so a log from today or yesterday
  is fresh: one missed night is tolerated, two is the signal.
- **Dedupe counts open issues only**, unlike `needs_human_issues.py`, which also counts closed ones. There the
  escalation file waits for a human; here the condition is live, so a silence that returns after the owner fixed it
  is news again. That is also why a landing log closes the issue — one left open would suppress the next silence,
  and the watchdog would work exactly once. Neither of those was in the acceptance criteria.
- **#12 now carries the `<!-- nightly-watchdog -->` marker**, appended to its body with a dated note saying why. It
  is the same silence, already escalated by hand, and without the marker the first cron run would have opened a
  near-duplicate and emailed the owner about something they already have. The watchdog will close #12 itself when a
  nightly log appears.

## One mistake, and the fix

Commit `52b633c` (the sprint records for this run) described the watchdog with the sentence "the watchdog closes #12
itself when a log lands". GitHub read "closes #12" as a closing keyword and closed
[#12](https://github.com/Nirmaypanchal/rapport/issues/12) — an open escalation to the owner — seconds after the push.
Reopened within the minute with a comment saying exactly what happened, since a silently reopened escalation is worse
than a visible mistake; `main` was not rewritten for it. The rule is now in `sprint/skills/all-sprint-automation.md`:
never write "closes/fixes #N" in a commit message unless you mean it, even when quoting what other automation does.
